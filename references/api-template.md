# API.md 模板 — API 设计

API 的请求/响应结构必须基于 DataModel.md 中的实体定义。

## 模板

```markdown
# [项目名称] - API 设计

## 基础信息
- **Base URL**：`/api/v1`
- **认证方式**：<!-- JWT / Session / API Key -->
- **数据格式**：JSON

## 端点列表

### [资源名]
- `GET /[资源]` — 列表查询，参数：<!-- 分页/筛选 -->
- `POST /[资源]` — 创建，请求体：<!-- 字段列表 -->
- `GET /[资源]/:id` — 详情
- `PUT /[资源]/:id` — 更新，请求体：<!-- 字段列表 -->
- `DELETE /[资源]/:id` — 删除

## 数据结构
<!-- 主要请求/响应的 JSON 结构示例 -->

## 错误码
<!-- 通用错误码定义 -->
```

## 对齐校验：API.md → DataModel.md

- 每个端点的数据字段是否能在 DataModel.md 中找到对应实体和属性？
- API 中的关系引用是否与 DataModel.md 中定义的一致？

## 后续约束

- 业务逻辑实现必须严格对齐 API.md 中的端点定义
- 前端交互实现中的 API 调用必须对齐 API.md
